## Plumbing — CLI, metrics, logging

- **CLI, not the Web UI.** `python run.py config.yaml -l …` produces identical metrics (`use_ui_logger: true` is read by the trainer, `toolkit/logging_aitk.py`, not the UI process). The only loss is the Web UI's own job list/dashboard.
- **Metrics live in `loss_log.db`, not `aitk_db.db`.** `sqlite_db_path` (`aitk_db.db`) only ever holds one status `Job` row, and only when the Web UI launched the run (`AITK_JOB_ID`); a CLI run leaves it untouched. The real file is `<training_folder>/<job_name>/loss_log.db` (WAL, safe to read during training). Schema: `steps(step, wall_time)`, `metric_keys(key, first_seen_step, last_seen_step)`, `metrics(step, key, value_real, value_text)`. Confirmed keys: `additional_model_loss`, `learning_rate`, `loss/ar_ce`, `loss/ar_kl`, `loss/loss` (**no** `nar_flow`); primary scalar `loss/loss`. Read it with `monitor_loss.py`, never hand-written SQL.
- `process[].type: "diffusion_trainer"` is the correct superset (`DiffusionTrainer(SDTrainer)` only adds no-op UI/API hooks); `verification.md`'s `'sd_trainer'` note is not a mismatch to fix.
- `log_dir` wraps every trainer, but TensorBoard writes to `log_dir/<job_name>_<timestamp>/` — glob one level down. `log_config: {log_every: 1}` at the process root is a **dead key** (never read by `LoggingConfig`), left in the YAML so it isn't mistaken for a missing feature. Redundant with `loss_log.db`.
- AI Toolkit logs **no** GPU utilization/temp/power (`performance_log_every` only prints a wall-clock breakdown). `gpu_logger.py` is the only source — confirm it runs before trusting an idle-GPU read.

## Dataset — formats, captions, naming

- 267 audio/caption pairs, all native `mp3, 48000 Hz, stereo` (== `YuE2AudioModel.sample_rate`); no conversion. `prepare_yue2_dataset.py --convert-wav` hardcodes `-ar 44100` (a real bug) — don't use it. `cache_latents_to_disk: true` is **mandatory** (else YuE2 raises "needs codec tokens in the latent cache").
- **Caption lyric format — binding on anything that builds prompts** (held-out set, eval tooling): drop the `///***///` line; collapse a bracketed tag whose content starts with a canonical section name (`Intro`, `Verse` [+number], `Chorus`, `Pre-Chorus`, `Bridge`, `Outro`, `Hook`, `Refrain`) to bare `[Section Name]`, dropping everything after the first `|`; drop any other bracketed tag (SFX/arrangement asides) and log it; never touch diacritics, the trailing `...`, or the Arabic wording. (Review bug found and fixed: the whitelist first lacked `Refrain`.)
- **Trigger word does not double.** `inject_trigger_into_prompt` (`toolkit/prompt_utils.py:715-748`) prepends `trigger + " " + caption` only when the trigger appears zero times; v2 captions carry a baked-in byte-equivalent `arabmaqamrock `, so `trigger_word` stays in the YAML. v1 captions had no trigger. (`setup.sh` clones ai-toolkit unpinned `main` — re-check if injection is suspected to have changed.)
- **Naming convention (user): no numeric versions.** The live dataset/run keeps its plain name; only a *superseded* artifact gets a suffix describing *why*. Applied: `yue2_dataset` is always current; v1 → `…_v1_style_only_obsolete`; a killed run → `…_crop60_killed`. Promotion is a storage-layer content swap (`GCP_DATASET_PATH`), no config path change. Keep an archive's folder name attached to its file (don't rename the `.safetensors` separately — it becomes ambiguous across datasets). v1 has **no surviving adapter** (its documented archive is absent from the project prefix).
- **Held-out status = lyric-line overlap, nothing else.** `INFERENCE/evaluation_alharith.json` is **not** clean (Hijaz 8/18, Kurd 6/24, Nahawand 6/24 share lines with training; Ajam 0/22 is clean) — the same poem section recurs across workspaces (267 captions = 157 distinct texts). Normalization (used everywhere): strip diacritics (U+064B–U+065F, U+0670) + `.` + whitespace, map U+0671→U+0627; a lyric line is any non-empty line not starting with `[` and not `///***///`. The replacement set (`INFERENCE/yue2_eval_heldout/`) is one pick per maqam, that maqam's own text, `shared_lines == 0` vs all 267, 24–28 lines, four workspaces; the Ajam pick shares 8 lines with `evaluation_alharith.json`'s clean Ajam entry (directly comparable). Open (user): which set the post-run eval uses.
- **Token counts: no overflow, don't re-check.** Real tokenizer, AR prefix vs `CONTEXT = 24576`: 267 captions 780–1631 (mean 1214), worst case (vs the 370 s max clip) leaves 13,690; held-out prompts 983–1237, worst case vs `duration: 360` leaves 14,334.

## Training config — why rank / EMA / cot / window

- **Rank 32** — all 267 captions are near-identical; a higher rank on a narrow caption space memorizes per-clip artifacts instead of the shared style. Lower if overfitting shows. **EMA** (`use_ema: true`, `ema_decay: 0.999`) is a run-to-run consistency lever, not peak quality.
- **`cot: "off"`** — captions carry no melodic/ABC info, so `cot: "full"` would pull SheetSage2 for no benefit at real cost. Flip only if the goal becomes shaping melodic structure (then pre-warm SheetSage2).
- **`train_window_frames: 0` (whole-song).** The implicit default (1500 = 60 s @ 25 fps) cropped one random 60 s window per step in `condition_noisy_latents()` and computed the NAR flow loss *and* `loss/ar_ce` on it, so the AR expert never saw a verse→chorus transition in one gradient — a hard ceiling no number of steps could fix. `0` disables cropping. Safe: AR context `24576/25 ≈ 983 s` vs the 370 s longest clip; the VAE's "60 s chunks" are an encode-time memory trick, not an architectural boundary. `content_or_style` left unchanged (a different axis), one variable at a time.
- **`sample.duration: 360` + real held-out lyrics** — so a checkpoint sample can show the intro→verse→chorus→outro arc *and* pronunciation (v1's lyric-free 120 s samples could show neither). Cost: sample generation scales with length (~226 s for a 120 s event on the A100; 360 s ≈ 3×, ×12 events).
- **v2 confirmed the lyric fix; `ar_kl` drift replicated.** `loss/ar_ce` ended ~0.35 below v1 (3.61 vs 3.97) — the mechanical consequence of the AR now receiving lyrics, **not** a quality claim (audio is judged by ear). `loss/ar_kl` rose unbroken to the end in **both** runs (v1 0.37→1.50, v2 0.39→**1.54**); `ar_kl_weight: 0.2` did not plateau it — a reproduced two-run trend, the first well-motivated lever for a next run (fewer steps, lower LR, or lower `ar_kl_weight`, one at a time). Cross-run loss values are directional (different prompt conditioning), not an A/B on audio.

## Lesson — a goal change invalidates every decision made under the old goal

- The goal moved from "style/timbre adapter" to "structurally coherent songs that sing the provided lyrics". Only the config consequence (`train_window_frames`) was caught; the dataset consequence (lyric-free captions) survived because it lived in a *build script's docstring*, not the config being audited. Cost: a full 3000-step run trained toward the wrong target for the lyric-following half, and a misdirected knob hunt.
- **Rules:** (1) on any goal change, list every artifact that encodes the old goal — dataset captions, `cot`/`do_separation`/loss weights, `sample.samples`, the eval protocol — and re-justify each; config is only one place. (2) Record deliberate omissions as decisions ("we left X out on purpose" has a premise; in a code comment it outlives it silently). (3) When a training input is empty by design, ask what the loss then cannot teach. (4) Test the goal metric *during* training, not only after. (5) When a result looks like a tradeoff, look for missing signal first.

## Run lifecycle — traps and policy

- **Same run name auto-resumes; it does not start fresh.** `get_latest_save_path()` globs `save_root` for the newest `<name>*.safetensors`/`.pt` and copies its embedded `training_info.step` into `start_step`; `optimizer.pt` loads too. A new/changed config pointed at a folder with checkpoints silently resumes; `train.start_step` only overrides the counter. `backup_to_gcp.py`'s manifest refuses only *different* run names, so a same-name relaunch would overwrite same-named GCS checkpoints and append to `loss_log.db` (indistinguishable runs). To restart: archive the output (distinct name, or move the local folder + `gsutil mv` the GCS prefix), restart the backup daemon for a fresh manifest. The latent cache is **not** invalidated (`train_window_frames` crops at train time only).
- **Reusing a run name** (user's convention: live runs get no number) means `name`/`log_dir`/`backup_to_gcp.py`'s `JOB_NAME` stay untouched. Safe only if all hold at launch: `output/` is empty before launch, the GCS restore rsync is **not** run first, and any smoke-test `.safetensors` is wiped (only matters at step 250+).
- **Extending a finished run overwrites the final adapter.** The end-of-run save (`BaseSDTrainProcess.py:2814`, `save()` with no step) writes `<run name>.safetensors` with no step suffix — extending past 3000 rewrites the exact artifact the converter consumed, and `max_step_saves_to_keep: 12` deletes the oldest numbered checkpoint. GCS is not append-only for that file. `train.start_step` is not protection; `network.pretrained_lora_path` is **not** a resume (weights only — no optimizer/EMA/step; untested). **Before extending:** copy the final adapter outside the run prefix (record its sha256), extend under a **new run name** with the checkpoint + `optimizer.pt` copied in, and the user types the command.
- **Cross-VM/cross-GPU resume** = restore the GCS `output/` prefix into `/content/ai-toolkit/output/<run>/`, launch the identical command (newest checkpoint auto-resumes). A run is portable only once a checkpoint exists **and** reached GCS (`save_every: 250` ⇒ first resumable point is step 250). The latent cache is per-VM (fresh VM rebuilds ~12 min). Never run the same run name on two VMs (shared GCS prefix/manifest). Performance-only knobs don't affect resume; changed hyperparameters/network/lr are a different experiment.
- **L4 vs A100 (measured).** Whole-song ran clean on both: L4 ~13.4 s/step (15.8 GB peak of 24); A100-SXM4-80GB median **3.10 s/step** (~4.3×, beats the ~2–2.6× spec ceiling). Colab break-even is 4.35×, so the A100 still costs ~1.7–2.2× more units — it buys turnaround, not savings. Don't reuse the 60 s-window run's ~7.8 s/step or ~6 h ETA (whole-song is ~1.7× slower per step).
- **Training-control policy.** The agent may auto-resume an **unchanged, already-approved** run after an unplanned interruption (same config + run name, nothing changed). It may **not** start a new run or resume with any changed config/hyperparameter without the human typing the command — a run finishing without errors is not a run being *right*.
- **Dataset/config decisions are the user's; the agent flags, never blocks** (the v2 build diverged from the then-`AGENTS.md` procedure; the agent surfaced it, the user chose to proceed).

## Backup & continuity

- **`loss_log.db` (and TensorBoard events) must not gate the settle wait.** `wait_for_settle` skips files still being written; `loss_log.db` + `-wal`/`-shm` are excluded by name, and `_settle_ignored()` also skips any path under `tensorboard/` or named `events.out.tfevents*` (rewritten every step). Missing the latter starved `output/` syncs entirely (no checkpoint reached GCS for ~1 h on the 2026-09-24 pron run). They are still uploaded — they just don't gate the pass. Symptom of a new always-written file: "pass complete: 2/3" repeating with no `output` sync.
- **Cadence is 5 minutes (was 15) for both daemons** — a 15-min cadence + VM death lost two finished renders (2026-09-25). `backup_to_gcp.py --interval-minutes` and `vm-continuity` both default to 5. Cost is bandwidth (~180 GB/mo for continuity), not GPU. Dated incident write-ups keep "15-min" as the value at the time.
- **Inference backup is a race against the ephemeral VM.** `--inference` syncs with `settle=False`, so a pass can upload a WAV mid-write (the next pass heals it). For long sweeps, fire `backup_to_gcp.py --inference --once` (incl. `--extra`) right after the last track rather than relying on the interval.
- **Continuity is idle-time only.** `vm-continuity` (OpenCode session backup) must never delay or divert a GPU-paid session; develop/test it only while the GPU is already busy or on an idle/CPU VM — never launch GPU work for it. `vm-continuity status` (exit 0 = healthy) reads `watch_status.json`; the loop self-heals with capped backoff. `setup.sh`'s `start_continuity_loop()` runs inside `job_vm_continuity`, *before* the setup-success gate (log `vm_continuity_install.log`). The documented `restore opencode -- --mode db|export` form works (fixed `6c4ddad`); `--db-path` targets an alternate DB without stopping the live service.

## Inference (audio.cpp + GGUF + LoRA)

- **`docs/models/yue2.md` is the source of truth for yue2 CLI flags** — read it first, not the source or guesswork. Length is `semantic_max_tokens` (25 frames/s); `--duration-seconds` is ignored and the model self-terminates under an ample cap; the generic `--temperature/--top-p/--top-k/--repetition-penalty` flags are **no-ops** (use the `semantic_*`/`abc_*` options).
- **T4 VRAM is governed by the attention kernel — force `yue2.attention=flash`.** On CC 7.5, `auto` picks eager NAR attention; eager OOMs at cap 6200, flash uses ~half the VRAM and passes it (cap 6200 → 7,607 MiB; cap 9000 → self-terminates at 6,355 frames / 7,683 MiB). An earlier "≤5800-frame ceiling" was a guess and is **retracted**. `auto`'s Volta/Turing ease is documented upstream; forcing flash on a T4 is the correct override, not a workaround. L4 (8.9) needs no override. VRAM figures: use the ggml runtime's 14,912 MiB (not `nvidia-smi`'s 15,360) for headroom.
- **Build:** bare `scripts/build_linux.sh` defaults to `--model-set full` (all 80+ families, ~30 min). Use `--model-set custom --models yue2 --cuda-arch <N> --ccache --target audiocpp_cli`; no Ubuntu+CUDA prebuilt exists. **Staging rule:** the prebuilt binary goes to `$AUDIOCPP_INFERENCE/bin/audiocpp_cli`, deliberately **not** under `/content/audio.cpp` (`job_audio_cpp` does `rm -rf` + re-clone). The workspace was renamed `audiocpp_gguf_test` → `audiocpp_inference`.
- **LoRA loading is native;** `yue2.ar_lora`/`yue2.nar_lora` + scales (a new session is needed to change them). It needs **unfused** SafeTensors (what `converter/convert_aitoolkit_yue2_lora.py` produces; re-running it reproduced the adapters byte-identically). `cot=off` matches this LoRA. **Use the BF16 main GGUF when a LoRA is loaded** (merging into Q8/Q4 dequant+requant is not equivalent).
- **Seeds:** accepted in `[0, 2^63)` but both AR and NAR seed `std::mt19937((uint32_t)seed)` — **use seeds below 2^32** (multiples of 2^32 collide). **A track is reproducible only as its WAV:** the seed does **not** reproduce across arch — re-rendering two tracks on a T4 with byte-identical inputs gave different WAVs from the L4/sm89 originals. **Every track gets a JSON sidecar** (seed, full command/options, prompt-file + GGUF/VAE/LoRA sha256s, checkpoint step, audio.cpp commit, GPU/arch/attention, cap, frame count, `truncated`, wall time, WAV sha256), written before generation. Filenames carry every varying parameter.
- **Inference runs are manual and file-reported.** The agent writes exact commands to `agent_notes/current.md` and **does not run them**; the user runs them in a separate terminal; the agent monitors by **reading** `out/*.log`, `_runs_status.log`, `_gpu.csv` and quotes lines (never paraphrases). (Changed after an OOM post-mortem where a prose summary asserted an unverified ceiling.)
- **Batch verdict criteria are fixed before generating.** Define what counts as "3000 is enough" vs "needs more training" *before* a batch (different failures → different levers: more steps, lower `ar_kl_weight`/LR, dataset changes). Hardware (user's 2026-09-21 figures, recheck pricing): T4 High-RAM is the inference workhorse; L4 optional; A100 is fine-tuning only.

## LoRA merging & the library

- **Merging two YuE2 LoRAs is an offline file merge** (`merge_pron_lora.py`; nothing loads two adapters at once). ai-toolkit's delta is `(alpha/rank)·(B@A)`; both inputs trained alpha==rank, so each saved file is exactly `B@A`. The user `--alpha` dial is folded into `B_pron`. Method: rank concatenation (32+8→40), dense delta never materialized.
- **The converter enforces a single rank** (`convert_aitoolkit_yue2_lora.py:207-208`): at alpha>0 the rank-32 NAR branch must be zero-padded to 40 (no-op on the delta) or conversion fails; at alpha=0 the pron block is dropped and no padding happens. **alpha=0 reproduces the live converted v2 adapters byte-for-byte** — but only if the merged input keeps v2's basename (`source_file` metadata is stamped with the input filename).
- **Verify merges by tensor digest or converted AR/NAR sha256 — never the merged *file* sha256** (`safetensors 0.8.0` writes `__metadata__` in nondeterministic HashMap order; two identical merges hashed `cf0d69b7…` vs `62e084a7…` while all 448 tensors and metadata are identical). `merged_sha256` in sweep manifests is a convenience record.
- **Canonical library `<base>/loras/`** — one place for current/deployable adapters (`audio_cpp/style/`, `audio_cpp/pron/`, `source/`); sweep/prototype adapters stay under their round prefixes, non-canonical. The map is `docs/LORA_INVENTORY.md` (do not re-derive by listing GCS). `bootstrap/setup.sh`'s `LORA_GCS` stages `audio_cpp/style/`; `backup_to_gcp.py --inference` does not mirror `converter/out` (the library is curated by hand). **Do not move/rename a current adapter without updating `docs/LORA_INVENTORY.md` + the `SOURCE_OF_TRUTH.md` row + GCS in the same change.**
- **The `pron_lora_ar_only_r8` donor is superseded by the long-aya Quran run (`quran_long_aya_r8_s10`).** The current (unlistened) candidates are the two `qfinal_a*` merges (v2 style + long-aya final, α 0.3/0.5). The family (15 `c3050/c4575/cfinal_a0.*` + 3 source pins) was archived to `<base>/archive/pron_lora_ar_only_legacy/` and the run prefix renamed `<base>/pron_lora_ar_only_r8_obsolete/` (2026-09-27, md5-verified). The config keeps its `name:` (configs are never edited), so the local output dir and the GCS archival prefix differ on purpose.
- **No adapter is "best"/"primary"/"winner" before the blind listen.** Describe candidates by parameters and mark them **unlistened**. **α is capped at 0.5** for this work; α>0.5 artifacts were moved to `<base>/archive/alpha_gt_0.5/` — do not rebuild them. Generated audio (`PRON_*_INPUT/`, `MAQAM_LYRIC_SWAP_INPUT/`) lives in GCS `<base>/listening/`, not the repo (untracked; history still holds the mp3s — purging needs a rewrite, not done).

## Handing over commands & run-control

- The user runs commands by hand in a real terminal; the agent's shell is a different session. Before presenting any long-running, background/detached, or state-changing command, load `skills/command-handover/SKILL.md` and state foreground vs detached, the output log, the stop command, and the resume command. New gotchas append to `docs/COMMAND_HANDOVER_GOTCHAS.md`.
- **Training is detached** via `train_ctl.py` (`start`/`status`/`stop`): spawns `Popen(start_new_session=True)` with SIGINT reset to `SIG_DFL` in the child, writes a pid/state file (`/content/logs/train.{pid,state.json}`), refuses a double-run, and verifies the pid before signalling. The SIGINT reset is load-bearing: a background job inherits `SIGINT=SIG_IGN` and a non-interactive shell cannot un-ignore it, so `kill -INT` (and `trap - INT`) is a silent no-op — a Python `signal.signal(SIGINT, SIG_DFL)` before `exec` works. `run.py` is still the engine; this is run-control only.
