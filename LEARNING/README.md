# Learning the stack — case study: this project

A sandbox for **understanding**, not running. This directory is deliberately
**outside the ops doc contract** (`../SOURCE_OF_TRUTH.md`, `../docs/README.md`):
nothing here is authority for operating the project. The runbooks stay on `main`.

## The deal (not a syllabus)

- **No units, no learning outcomes, no schedule.** We follow *your* curiosity.
  If a plan ever feels like a course, we throw it out — that mode is what killed
  the earlier attempts.
- **Anchored to real artifacts.** Every idea gets tied to a file, command, or
  number in *this* project — never a textbook example.
- **Depth dial, your call.** For any topic, pick:
  1. *analogy* — ~2 min, no jargon (default when you say "quick")
  2. *working intuition* — ~10 min, enough to reason about it
  3. *hands-on* — open the real code, run a tiny thing, see the math
- **One sitting = one thread.** Stopping when you've had enough is success, not
  quitting. We can always resume from `log.md`.
- **Parking lot.** Anything off-thread goes in `log.md` — never lost, never a
  detour.
- **Teach-back.** You explain it in your words; I correct. That is the only real
  progress signal (reading feels good but doesn't stick).
- **GPU etiquette.** Hands-on GPU experiments wait for a free GPU. Concept work
  and CPU toys run anytime.

## Files here
- `map.md` — the living picture of the whole machine, with "you are here".
- `glossary.md` — terms met in this project, in *your* words.
- `log.md` — one entry per sitting + the parking lot.

## North star (not a test)
You have "learned enough" when you can tell the story of how one of *your* songs
gets made, start to finish, and say why each part is there. Past that: as deep as
your curiosity goes — and you get to decide when it's enough.
